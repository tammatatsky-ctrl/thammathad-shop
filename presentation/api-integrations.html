แคช (ชั้นกลาง)

ผลลัพธ์ถูกเก็บใน Django Cache ก่อนถึง API จริง → เปิดหน้าเดิมซ้ำเร็วขึ้นมาก และยิง API น้อยลง

View บาง

View ทำแค่ “เรียก service + ส่ง context” — ไม่มี business logic และไม่มีโค้ดต่อเน็ตอยู่ใน view

สัญญาณเดียวกัน

ทุก service ใช้รูปแบบเดียวกับ ExchangeRate: classmethod, cache, timeout, ไม่ throw

with urllib.request.urlopen(req, timeout=6) as resp:
    parsed = cls.parse_ics(resp.read().decode('utf-8', 'replace'))
data = {d: n for d, n in parsed.items() if d.year == year and ...}
cache.set(key, data, cls.HOLIDAYS_TTL if data else cls.HOLIDAYS_FAIL_TTL) ← ล่มก็แคชสั้นไว้ลองใหม่

หลักการออกแบบ

7 หลักการที่ใช้กับทุก API

  1. เรียกจากฝั่งเซิร์ฟเวอร์เท่านั้น — เบราว์เซอร์ไม่ยิง API ตรง (ซ่อน key, เลี่ยงปัญหา CORS, คุมรูปแบบข้อมูลได้)
  2. Service Layer เป็นจุดเดียว — โค้ดต่อเน็ตทั้งหมดอยู่ใน services.py; ถ้าเปลี่ยนผู้ให้บริการ แก้ที่เดียว
  3. แคช + TTL — อัตราแลกเปลี่ยน 6 ชม. · ตำแหน่ง/แปล/วันหยุด 24 ชม. · หมวดหมู่สินค้า 60 วินาที (ลด latency และโควตา)
  4. Graceful Degradation — API ล่ม/ช้า → คืน None/'' แล้วเทมเพลตซ่อนฟีเจอร์นั้นเอง หน้าเว็บไม่มีวันพัง
  5. Key-gating — บริการที่ต้องมีคีย์ (Gemini/SlipOK) มี enabled(); ไม่มีคีย์ = ซ่อนปุ่ม/ฟอร์มทั้งชิ้น
  6. Timeout + User-Agent ชัดเจน — 4–6 วินาที กันหน้าค้าง และสุภาพต่อผู้ให้บริการ
  7. ทดสอบได้แบบไม่ต้องต่อเน็ต — เทสต์ mock urllib.request.urlopen → ผลการทดสอบคงที่ (deterministic)

โบนัส: ทั้งหมดเขียนด้วยไลบรารีมาตรฐาน (urllib, json, re, hashlib) — ไม่เพิ่ม dependency ให้โปรเจกต์เลย

API ที่ 6–7

บริการที่ต้องมีคีย์ — ซ่อนตัวเองเมื่อไม่มีคีย์

SlipOK — OCR ตรวจสลิป ต้องมี key

  • services.py:498 · views.py SlipVerifyView + RateLimit
  • templates/slip_upload.html (ถูก include ใน order_success.html)
  • ไม่มี SLIPOK_API_KEY → คืน 503 + ซ่อนฟอร์มอัปโหลด

  • services.py:598 · views.py ProductDescribeAIView

สรุป

สิ่งที่ระบบทำได้แล้ว

จุดเด่นเชิงวิศวกรรม

  • ต่อ API ภายนอก 4 บริการใหม่ — ไม่ต้องสมัคร ไม่มีค่าใช้จ่าย ไม่เพิ่ม dependency
  • ทุกบริการอยู่ใต้สัญญาเดียว: cache + timeout + fallback + ทดสอบได้
  • ค้นพบและแก้ปัญหาข้อมูลจริง (วัน observance ปนใน ICS) และข้อจำกัดจริง (GeoIP ไทยหยาบ) — เลือกใช้อย่างตรงไปตรงมา
  • เปิด REST API พร้อมเอกสาร OpenAPI/Swagger + throttle กันการใช้งานผิดวัตถุประสงค์

ประโยชน์ต่อผู้ใช้

  • ลูกค้าเห็นราคาเทียบสกุลเงิน และวันจัดส่งที่ข้ามวันหยุดจริง
  • เจ้าหน้าที่กรอกสินค้าเร็วขึ้นด้วยปุ่มแปลที่ไม่ต้องมีคีย์
  • ระบบไม่พังและไม่ค้าง แม้บริการภายนอกจะล่ม
  • ข้อมูลสำคัญ (สลิป, ที่อยู่) ไม่ถูกส่งออกนอกระบบเกินจำเป็น
